## Umgesetzte Unterstützung und Nachweise

`tools/p0-completion-plan.js` rechnet die fehlenden Zugänge, Nachweise und
Bestandsreviews aus einem gültigen gemeinsamen Snapshot mit der vorhandenen
Policy. Es erstellt eine editionsgenaue priorisierte Reviewliste, eine separate
kurzfristige Liste und Neuprüfungen auslaufender Nachweise. Ganzzahlige
Anforderungen verwenden keine gerundeten Prozentanzeigen.

```powershell
npm run plan:p0 -- --snapshot exports/mein-paket/catalog-snapshot.json --out exports/mein-paket/completion-plan.json
npm run test:p0-plan
```

Neue Messungen müssen innerhalb von fünf Minuten verwendet werden. Historische
Auswertung benötigt ausdrücklich `--at-snapshot-time` und wird als Replay
gekennzeichnet. Ausgaben bleiben exklusiv unter `exports/`; vorhandene Dateien
und verlinkte Pfade außerhalb dieses Bereichs werden nicht überschrieben.
Das Werkzeug schreibt weder Datenbankwerte noch Nachweise und erteilt keine
Releasefreigabe. Die bisherigen Daten-Gates, RPCs und UI bleiben unverändert.

Lokale private Belege: `exports/p0-20261006/catalog-snapshot.json`,
`quality-report.json`, `completion-plan.json` (ausdrücklicher Replay des Messstands),
`candidate-counts-tool-response.json`, `candidate-audit/diagnostic.json`,
`source-artifact-manifest.json`, `research-candidate-identity.json`,
`research-paderborn-bietigheim.json`, `research-boennigheim-registration.json`, `review-context.json` und
`bietigheim-single-field-correction.json`.
Abschlussmessung: `final-catalog-snapshot.json`, `final-completion-plan.json`
und `final-quality-report.json`. Frühere Postflightdateien bleiben als Messverlauf
erhalten. Paderborn-Belege: `paderborn-2027-program-extract.txt`,
`paderborn-2027-program-page-2.png` und `paderborn-proposal-rejection.jpg`.
Produktiv erfolgten ausschließlich Bietigheims belegte Statuskorrektur und vier
begründete Vorschlagsablehnungen (drei Bietigheim, eine Paderborn) im vorhandenen Adminweg. Keine neue Edition,
Migration, Vollattestation oder regulärer Datenrelease ausgeführt.
