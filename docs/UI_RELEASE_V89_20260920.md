# Eigenständige Eventdetailseiten – Release v89, 20.09.2026

Der gemeldete Klick auf „Open detail page“ führte mit v86 zurück in denselben
Karten-Drawer. Die damalige Prüfung bestätigte eine funktionierende Kurzansicht,
aber keine eigenständige Detailseite. Der echte Klick wurde vor der Änderung
auf der Hauptdomain reproduziert: identische URL vorher/nachher, kein
`body.event-detail-page`, weiterhin offener Drawer.

## Korrektur

Fehlende statische Eventpfade führen jetzt zur separaten öffentlichen
`event-detail.html?event=<edition_slug>`. Sie zeigt die veröffentlichte Edition
aus `public_event_archive`: Name, Datum, Ort, Distanzen, Adresse, Beschreibung,
Anmeldestatus und Quellen. Die Anfrage verwendet nur den öffentlichen Schlüssel,
ausgewählte öffentliche Spalten, den genauen Slug und höchstens zwei Zeilen.
Es gibt keine Adminoberfläche und keinen Import von `js/app.js` oder `js/supabase.js`.

Die tatsächlichen Produktionsspalten wurden vorab lesend geprüft; zusätzliche
Felder aus abweichenden lokalen Migrationen werden nicht vorausgesetzt. Inhalte
werden als Text gerendert. Links erlauben ausschließlich HTTP(S) ohne eingebettete
Zugangsdaten. Unbekannte, ungültige oder nicht ladbare Events erhalten eine
sichtbare Meldung; bei Ausfall kann eine exakt passende veröffentlichte lokale
Edition mit ausdrücklich genanntem Exportdatum angezeigt werden. Eine erfolgreiche
leere Liveantwort wird nicht durch alte Daten ersetzt.

Die Saisonfunktion nutzt das bestehende Detailseitenmodul und dieselbe
Eventidentität. Bestehende statische Seiten bleiben erhalten. Eventlinks bevorzugen
den veröffentlichten Editions-Slug, wie der statische Seitengenerator; ältere
Datensätze behalten die bisherige Namens-/Jahresableitung.

Die dynamische Seite bleibt `noindex`; ein neuer statischer SEO-/Datenexport ist
nicht Teil dieses UI-Fixes. Die P0-Datenfreigabe und ursprünglichen Daten-Gates
bleiben unabhängig davon bestehen.
